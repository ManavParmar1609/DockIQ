# Deployment — the $0 stack

| Piece | Host | Free-tier facts that matter |
|---|---|---|
| Database | **Neon** Postgres | 0.5 GB, scales to zero after 5 min idle, wakes in < 1 s |
| API + WebSocket | **Render** free web service | 512 MB, Docker, WebSockets supported, 750 instance-hours/month. **Sleeps after 15 min without traffic; the first request after that takes about a minute** |
| Frontend | **Vercel** Hobby | Static build of `frontend/` |
| CI | **GitHub Actions** | Runs `.github/workflows/ci.yml` on every push and PR |
| Assistant model | NVIDIA API catalog *(optional)* | Free developer key from build.nvidia.com. Without it the assistant runs on its rules-based router |

No card is required anywhere. **Before a live demo, open the app a minute ahead** so Render wakes the
API: the sign-in screen says it is waking the server until the API answers. The simulation does not
mind the sleep: its clock is a function of time, so it catches up on the first request.

> *Koyeb was the original API host. Mistral AI acquired it in February 2026 and its free tier is
> closed to new sign-ups, so the API moved to Render. The Dockerfile is host-neutral.*

> Demo credentials only: every seeded account shares `DEMO_PASSWORD`. Deploy it only with the seeded
> fictional data. See `.claude/rules/security.md`.

---

## 1. Neon — the database

1. Create a project at neon.tech. `us-east-2` (Ohio) pairs with Render's Ohio region in
   `render.yaml`; change `region:` there if you pick another.
2. Open **Connect** and copy the connection string. **Pooled or direct both work**: the API detects
   Neon's pooled host (`-pooler`) and switches asyncpg to PgBouncer-safe settings (no client pool,
   unique prepared-statement names, no statement cache). Paste it exactly as Neon shows it,
   `sslmode=require` and `channel_binding=require` included; the API converts them for asyncpg.
3. Put it **only** in Render's secret field (step 2): never in a file, a commit or a chat. If it has
   been exposed, reset the role's password in Neon (**Roles → Reset password**) and use the new one.

The schema is created by Alembic migrations when the API boots, and the demo data is seeded on the
first boot. There is nothing to run by hand.

## 2. Render — the API

The repository carries a Blueprint, `render.yaml`. In the Render dashboard:

1. **New → Blueprint**, connect GitHub, pick the DockIQ repository, branch `main`.
2. Render reads `render.yaml` and asks for the secret values:

| Name | Value |
|---|---|
| `DATABASE_URL` | the Neon connection string from step 1 |
| `CORS_ORIGINS` | your Vercel URL, e.g. `https://dockiq.vercel.app` (comma-separate several). Not known on the first deploy: enter `https://example.invalid`, then update it after step 3 |
| `DEMO_PASSWORD` | the password every demo account signs in with |
| `NVIDIA_API_KEY` | optional; leave empty for the rules-based assistant |

`JWT_SECRET` is generated by Render (a random 256-bit value); `NVIDIA_MODEL` and `WMS_MODE` are set in
the file. `ENVIRONMENT=production` is baked into the image. On every boot the container runs
`python -m app.seed` (migrate to head; seed only if the database is empty), then starts uvicorn on
Render's `$PORT`. Redeploys never duplicate or wipe data. Every push to `main` redeploys.

Check it: `https://dockiq-api.onrender.com/api/health` → `{"status":"ok"}`. (If the name is taken,
Render adds a suffix; the service page shows the URL.)

## 3. Vercel — the frontend

Import the repository, set **Root Directory** to `frontend` (framework preset: Vite, Node.js
version **24.x** in Project Settings), and set one environment variable:

| Name | Value |
|---|---|
| `VITE_API_URL` | the Render origin, e.g. `https://dockiq-api.onrender.com`, with no trailing `/api` |

The WebSocket URL is derived from it (`https` → `wss`, path `/ws`). A production build **refuses to
run** without `VITE_API_URL`, so a misconfigured deploy fails in the build log instead of shipping an
app that silently receives HTML from every API call.

Then set `CORS_ORIGINS` on Render to the Vercel URL; Render redeploys when you save.

## 4. Resetting the demo data

The demo ages: seeded timestamps are relative to when it was seeded. To reset, run the seed with
`--reset` against the Neon database **from your machine** (it refuses when `ENVIRONMENT=production`):

```powershell
cd backend
$env:DATABASE_URL = "<the Neon connection string>"
uv run python -m app.seed --reset
Remove-Item Env:DATABASE_URL
```

The simulation alone resets from the app: **Simulator → Reset**.
